# 数据文件

## 目录用途

- `input/`：程序启动时加载的基础数据。
- `output/`：命令行程序和文件读写测试生成的结果。

所有数据均为 UTF-8 CSV。加载顺序为：节点 → 道路 → 充电站 → 充电桩 → 车辆。

## `nodes.csv`

道路节点、车辆起点和充电站入口。

```csv
id,x,y,type
1,100.00,200.00,0
```

| 字段 | 说明 |
| --- | --- |
| `id` | 全局唯一节点编号 |
| `x`, `y` | 地图绘制坐标 |
| `type` | 节点类型 |

节点类型：

- `0`：普通道路节点；
- `1`：车辆起始位置；
- `2`：充电站入口。

## `roads.csv`

道路连接关系。

```csv
from,to,distance_km,travel_minutes,two_way,road_level
1,2,0.850,1.200,1,2
```

| 字段 | 说明 |
| --- | --- |
| `from`, `to` | 起点和终点节点编号 |
| `distance_km` | 道路距离，供耗电估算使用 |
| `travel_minutes` | 预计通行时间，作为 Dijkstra 边权 |
| `two_way` | `1` 表示加载时同时添加反向边，`0` 表示单向 |
| `road_level` | 道路等级，影响地图线宽 |

道路等级：

- `0`：支路；
- `1`：次干路；
- `2`：主干路；
- `3`：快速路；
- `4`：车辆或充电站接入道路。

## `stations.csv`

```csv
id,node_id,name
101,501,示例充电站
```

`node_id` 必须引用类型为充电站入口的有效节点。

## `chargers.csv`

```csv
id,station_id,power_kw,state
1001,101,120.00,0
```

| 字段 | 说明 |
| --- | --- |
| `id` | 全局唯一充电桩编号 |
| `station_id` | 所属充电站编号 |
| `power_kw` | 额定充电功率 |
| `state` | 初始状态 |

输入文件只接受以下初始状态：

- `0`：空闲；
- `2`：故障。

`1` 表示运行中的充电状态，不允许作为初始值加载。

## `vehicles.csv`

```csv
id,node_id,battery_percent,target_percent,capacity_kwh,urgency
201,1001,35.00,90.00,75.00,2
```

| 字段 | 说明 |
| --- | --- |
| `id` | 全局唯一车辆编号 |
| `node_id` | 初始位置节点 |
| `battery_percent` | 初始电量百分比 |
| `target_percent` | 目标电量百分比 |
| `capacity_kwh` | 电池容量 |
| `urgency` | 紧急程度，取值 1～3 |

## 当前示例规模

- 305 个节点：240 个道路节点、60 个车辆起点和 5 个充电站入口；
- 442 条道路记录；
- 5 个充电站；
- 24 个充电桩，每站 4～6 个；
- 60 辆车，位于 60 个不同起点。

示例坐标、距离和时间仅服务于仿真，不是现实导航数据。

## 输出文件

`fileio_save_all` 保存基础数据快照；内部有向边会以 `two_way=0` 分别写出。`fileio_save_vehicles` 保存车辆当前运行状态：

```csv
id,node_id,battery_percent,state,station_id,charger_id
```

## 数据约束

- 所有编号必须唯一，且引用对象必须已存在。
- 距离、通行时间、充电功率和电池容量必须为正数。
- 电量和目标电量必须处于有效百分比范围。
- 修改输入数据后应运行整体联调测试，确认车辆能获得有效推荐并完成充电。
