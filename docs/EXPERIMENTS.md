# 调度对照实验说明

本文说明如何使用 GTK 4 前端分别运行“本项目模式”和“对照实验模式”，以及界面统计指标的计算口径。实验用于观察不同站点推荐和排队策略在同一路网与车辆数据下的表现，不代表现实城市交通结论。

## 两种实验策略

| 模式 | 充电站选择 | 站内排队 |
| --- | --- | --- |
| 本项目模式 | 综合行驶时间、预计等待时间、预计充电时间与低电量风险 | 动态优先级最大堆 |
| 对照实验模式 | 选择行驶时间最近的有效充电站 | 严格先来先服务 |

为了便于比较，两次实验应使用相同的 CSV 输入数据、仿真时长、提交方式和持续车流设置。

## 指标口径

统计只计入已经完成充电的车辆。

| 指标 | 计算方式 |
| --- | --- |
| 总完成时间 | `完成时刻 - 请求提交时刻` |
| 平均总完成时间 | 已完成车辆总完成时间之和 ÷ 完成车辆数 |
| 最大总完成时间 | 已完成车辆总完成时间最大值 |
| 排队时间 | `首次开始充电时刻 - 到站时刻` |
| 平均排队时间 | 已完成车辆排队时间之和 ÷ 完成车辆数 |
| 最大排队时间 | 已完成车辆排队时间最大值 |
| 平均行驶时间 | 已完成车辆推荐路径行驶时间之和 ÷ 完成车辆数 |
| 累计完成车辆数 | 当前模式完成充电的车辆次数 |
| 单位时间完成数 | `累计完成车辆数 × 60 ÷ 已运行仿真分钟数` |

时间类指标越低越好，吞吐量越高越好。界面中的百分比使用对照实验作为基准：

```text
时间类优化率 = (对照值 - 项目值) / 对照值 × 100%
吞吐量提升率 = (项目值 - 对照值) / 对照值 × 100%
```

因此，时间类指标的正值表示本项目耗时更少；平均行驶时间可能因为综合推荐主动选择较远但等待更短的站点而上升。

## 推荐实验步骤

1. 从项目根目录启动 GTK 4 程序。
2. 点击“重置”，确认车辆、站点和统计数据回到初始状态。
3. 选择“对照实验模式”。
4. 设置仿真时长，例如 240 或 1000 分钟。
5. 固定“自动提交”和“持续车流”的开关组合。
6. 点击“提交下一批”或开启自动提交，然后点击“开始”。
7. 仿真结束后记录对照实验统计行。
8. 再次点击“重置”，切换到“本项目模式”。
9. 保持步骤 4～5 的参数不变，重新运行并记录统计行。
10. 保存完整界面截图，并记录当前 Git 提交哈希。

| 对照实验 |  |  |  |  |  |  |  |  |
| 本项目 |  |  |  |  |  |  |  |  |

建议同时记录：

- Git 提交哈希；
- 五个输入 CSV 的版本；
- 仿真时长与运行速度；
- 自动提交、持续车流是否开启；
- 每次实验的运行日期和截图；
- 是否修改推荐权重、优先级公式或充电桩状态。

## 解释结果时的注意事项

- 综合推荐的目标是缩短总完成与排队时间，不保证行驶距离最短。
- 持续车流会重复产生车辆请求，累计完成数可能超过初始车辆数。
- 两种模式必须分别完整运行；在同一次未重置的仿真中切换模式会破坏可比性。
- 当前输入数据表达相对路网关系，不是现实导航、实时交通或真实充电站运营数据。
- 若随机批次或持续车流状态发生变化，应进行多次重复实验并报告均值，而不是只报告一次最好结果。
