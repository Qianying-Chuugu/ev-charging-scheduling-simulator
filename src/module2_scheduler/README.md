# 模块 2：排队调度与等待时间估算

## 模块定位

模块 2 使用二叉最大堆维护充电站等待队列，并根据紧急程度、电量和等待时间动态调整车辆优先级。推荐模块还会调用本模块模拟当前队列，以估算新车辆到站后的等待时间。

## 动态优先级

```text
优先级 = 紧急程度 × 30
       + (100 - 当前电量百分比) × 0.5
       + 等待时间 × 0.2
```

优先级相同时，先比较到达时间；到达时间仍相同时，请求序列号较小者优先。

## 公开函数

| 函数 | 作用 |
| --- | --- |
| `scheduler_calc_priority` | 更新请求的等待时间和动态优先级 |
| `scheduler_push` | 计算优先级并把请求压入最大堆 |
| `scheduler_pop` | 取出当前优先级最高的请求 |
| `scheduler_rebuild` | 重新计算全部请求并自底向上建堆 |
| `scheduler_estimate_wait` | 在不修改真实队列的前提下估算等待时间 |

## 最大堆流程

- 插入：请求加入数组末尾，再执行 `sift_up`。
- 弹出：取出堆顶，把末尾元素移到堆顶，再执行 `sift_down`。
- 动态刷新：重新计算队列中全部优先级，然后从最后一个非叶节点开始建堆。

## 等待时间估算

1. 收集所有非故障充电桩的功率和剩余任务时间。
2. 复制真实等待请求，避免修改真实堆和请求字段。
3. 按车辆预计到达时刻重新计算副本优先级。
4. 按最大堆顺序逐个弹出请求。
5. 每次把任务分配给累计负载最小的充电桩。
6. 用最早空闲时刻减去新车辆的行驶时间，得到到站后的预计等待时间。

## 复杂度

- 插入或弹出：`O(log n)`；
- 重建堆：`O(n)`；
- 等待估算：`O(n log n + c)`，其中 `n` 是排队请求数，`c` 是可用充电桩数。

## 注意事项

- 本模块不拥有请求内存，只维护 `Station.queue` 中的指针。
- 没有可用充电桩或参数非法时，等待估算返回负值。
- 当前权重明显强调紧急程度；调整系数会直接改变实验结果，应同步更新文档和测试。
