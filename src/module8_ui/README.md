# 模块 8：GTK 4 图形界面

## 模块定位

`gtk4_ui.c` 实现单窗口 GTK 4 前端、地图绘制、用户交互和实验统计。图、调度、实体、推荐和仿真规则仍由后端模块负责；前端只组合接口，并实现批次、持续车流和对照实验等展示逻辑。

## 界面结构

| 区域 | 功能 |
| --- | --- |
| 顶部 | 数据刷新、批次提交、自动提交、持续车流、实验模式、时长和速度控制 |
| 中央 | 路网、车辆、充电站和推荐路径地图 |
| 左侧 | 车辆选择、电量信息、推荐计算、站点选择和请求提交 |
| 右侧 | 站内充电与排队状态、充电桩维护和新增设备 |
| 底部 | 本项目与对照实验的实时统计表 |

左右操作窗可折叠并从内侧拖动调整宽度；统计面板可独立收起。

## 主要功能函数

### 数据和视图

| 函数 | 作用 |
| --- | --- |
| `load_data` | 原子加载数据并初始化仿真及前端状态 |
| `refresh_view` | 统一刷新状态、统计、车辆、充电桩、队列和地图 |
| `install_css` | 注册界面配色和控件样式 |
| `activate` | 创建窗口并组合全部界面区域 |

### 推荐与提交

| 函数 | 作用 |
| --- | --- |
| `recommend_vehicle` | 为当前车辆计算推荐列表 |
| `submit_selected` | 向当前选择的充电站提交车辆请求 |
| `prepare_vehicle_batches` | 随机打乱车辆并划分批次 |
| `submit_next_batch` | 提交预设批次或持续车流批次 |

### 仿真和实验

| 函数 | 作用 |
| --- | --- |
| `timer_tick` | 收集时间步、推进仿真并触发自动提交 |
| `start_simulation` | 启动定时器；不会自动提交第一批 |
| `reset_simulation` | 重置后端和前端实验状态 |
| `control_simulation_step` | 执行最近站点与先来先服务对照逻辑 |
| `track_statistics_after_step` | 累计完成、排队、行驶和吞吐量指标 |

### 地图交互

| 函数 | 作用 |
| --- | --- |
| `draw_map` | 按背景、道路、节点、站点和车辆顺序绘制地图 |
| `on_map_pressed` | 点击选择车辆或充电站 |
| `on_map_scroll` | 缩放地图 |
| `on_map_drag_begin` / `on_map_drag_update` | 拖动平移地图 |
| `reset_map_view` | 恢复完整路网视图 |

## 批次与持续车流

- 每次加载数据会生成新的随机场景种子。
- 60 辆车被打乱后按每批最多 12 辆均匀划分。
- “开始”只启动仿真时钟，车辆由手动或自动批次提交。
- 自动提交每 10 个仿真分钟尝试提交下一批。
- 持续车流开启后，完成车辆在 5～10 个仿真分钟后重置到随机车辆节点，并进入待提交队列。
- 同一次加载后的重置复用场景种子，便于两种实验模式公平比较。

## 实验模式

- **本项目模式**：后端综合推荐 + 动态优先级最大堆。
- **对照实验模式**：选择行驶时间最短的有效站点 + 严格先来先服务。

两种模式的统计数据分别保存，界面显示平均/最大总完成时间、平均/最大排队时间、平均行驶时间、累计完成数和单位时间吞吐量。

## 地图绘制

- 道路等级决定线宽；道路使用白色外框增强可读性。
- 推荐路径以橙色显示，车辆经过的路段会从高亮路径中移除。
- 空闲车辆使用蓝色汽车图标，行驶车辆使用橙色图标。
- 充电站图标尺寸大于车辆图标，当前选择站点带黄色外圈。
- 图标加载失败时使用内置回退图形。

## 资源和路径

前端从以下相对路径读取内容：

```text
data/input/*.csv
assets/icons/car-front.png
assets/icons/charging-station.png
```

运行时应把项目根目录设为当前工作目录。

## 构建

```bat
构建GTK4.bat --no-pause
```

输出为 `build/charging_system_gtk4.exe`。

## 依赖

依赖 GTK 4、Pango/Cairo、模块 1～7 和模块 9。
